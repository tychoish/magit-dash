* Overview

=magit-dash= is a tabulated-list dashboard for tracking multiple local git
repositories from a single buffer.  Each registered repo shows its current
branch, fetch age, ahead/behind counts, dirty state, and configured
auto-sync operations.  Selecting a repo opens a per-repo overview buffer with
recent log, PR counts (via the GitHub CLI), and magit action shortcuts.

A companion PR dashboard (=magit-dash-gh-pr=) and CI log fetcher
(=magit-dash-gh-actions=) are provided as optional modules.

Repositories are registered with =magit-dash-register= (typically in your
=user/= or personal init file) and the dashboard is opened with
=magit-dash-open=.

* Installation
** package-vc.el

Requires Emacs 29.1+.  Run once to clone and register the package:

#+BEGIN_SRC emacs-lisp
(package-vc-install '(magit-dash
                      :url "https://github.com/tychoish/magit-dash"))
#+END_SRC

** use-package with VC

Requires Emacs 30+.  Installs on first load if not already present:

#+BEGIN_SRC emacs-lisp
(use-package magit-dash
  :vc (:url "https://github.com/tychoish/magit-dash"))
#+END_SRC

** use-package with load-path

#+BEGIN_SRC sh
git clone https://github.com/tychoish/magit-dash ~/path/to/magit-dash
#+END_SRC

#+BEGIN_SRC emacs-lisp
(use-package magit-dash
  :load-path "~/path/to/magit-dash"
  :commands (magit-dash-open magit-dash-open-other-window))
#+END_SRC

* Auto-sync hooks and operations

Each auto-sync operation (=fetch=, =pull=, =commit=, =push=, and the =sync=
meta-operation that runs them together) can take a =:pre= hook, a =:post=
hook, and an =:operation= override, all under one =:hooks= keyword passed
to =magit-dash-register=:

#+BEGIN_SRC emacs-lisp
(magit-dash-register
 :name "myrepo" :path "~/src/myrepo"
 :auto-fetch t :auto-commit t
 :hooks (:fetch  (:post (docs))               ;; docs = a :commands label
         :commit (:pre  (lint-staged))
         :sync   (:operation orchestrate      ;; full pipeline replacement
                  :post      (recompile-vendored))))
#+END_SRC

- =:pre= — targets run before the operation; a target signaling an error
  skips the operation (reported as =skipped=).
- =:post= — targets run after the operation succeeds (=ok= or a no-op
  =skipped=); failures here are logged but never fail the overall sync.
- =:operation= — replaces the default implementation for that operation.
  For =fetch=/=pull=/=commit=/=push= the step still only runs when its own
  =:auto-fetch=/=:auto-pull=/=:auto-commit=/=:auto-push= flag is set;
  for =sync= it replaces the *entire* default pipeline outright —
  fetch/pull/commit/push and their own settings are not consulted at all.

A target is a symbol (looked up as a label in =:commands=), a string (run
as a shell command in the repo directory), or a function of
=(REPO ON-COMPLETE)= where =ON-COMPLETE= accepts =ok=, =skipped=, or =error=.

=magit-dash-global-hooks= applies =:pre=/=:post= hooks (no =:operation=)
across every registered repo, using the identical shape.  Ordering wraps
outermost-to-innermost: for =:pre=, global hooks run before repo hooks; for
=:post=, repo hooks run before global hooks (global closes last). Set it
with =magit-dash-set-global-hooks= rather than =setq=, so the shape is
validated:

#+BEGIN_SRC emacs-lisp
(magit-dash-set-global-hooks '(:sync (:post (notify-dashboard))))
#+END_SRC

#+RESULTS:
** ~magit-dash-open~ [Command]

Open the repository dashboard buffer in another window. Signals ‘user-error’ when ‘magit-dash-repo-list’ is empty.

** ~magit-dash-view~ [Command]

Open the overview buffer for the repository at point.

** ~magit-dash-sync-repo~ [Command]

Select a repository interactively and run its configured auto-sync operations.

** ~magit-dash-open-repo~ [Command]

: (fn &optional ROOT)

Select a repository and open its magit status buffer.

Context-aware collection: - In a magit-status buffer: scans from the parent of the current repo and merges ‘~/’ at depth 1, so sibling repos and home-level repos appear together. - In a directory that is itself a git repo: only the repo’s worktrees and submodules are offered (use a prefix arg to override and scan subdirs). - Otherwise: scans subdirectories of ‘default-directory’.

Live magit-status buffers are always included and marked "[open]"; selecting one switches to it directly without reopening it.

With a prefix argument, prompt for ROOT and scan it normally regardless of the above context rules.

** ~magit-dash-open-other-window~

Open the repository dashboard buffer in another window. Signals ‘user-error’ when ‘magit-dash-repo-list’ is empty.

** ~magit-dash-ci-dispatch-fix-operation~

: (fn REPO)

Download the latest CI run’s artifacts for REPO and dispatch a fix-CI prompt. Uses REPO’s cached :ci-status when present; otherwise fetches it first via ‘magit-dash-gh-ci-fetch’ before proceeding, so this can be called without a prior manual CI-status fetch.  Signals ‘user-error’ when REPO does not have :include-ci set, or when no CI run is found for it even after fetching.

** ~magit-dash-gh-ci-open-last-run~

: (fn REPO)

Open the URL of the most recent CI run for REPO in the browser. Does nothing when no CI status is cached for REPO.

** ~magit-dash-gh-actions-fetch-for-pr~

: (fn PR-NUMBER REPO-DIR)

Fetch GitHub Actions CI logs for PR-NUMBER using REPO-DIR as the working directory. PR-NUMBER is an integer.  REPO-DIR must be a local checkout of the repository so that ‘gh’ can resolve the remote when listing and downloading runs.

** ~magit-dash-gh-actions-fetch~ [Command]

: (fn &optional RUN-ID)

Download GitHub Actions CI logs for the current branch. When RUN-ID is non-nil, fetch that specific run without prompting. Otherwise list recent runs and prompt for a selection.

Creates an artifact directory under plans/ containing: run-info.json        — full run metadata run-logs.ghlog       — complete step logs (opens in ‘magit-dash-gh-actions-log-mode’) run-failed-logs.ghlog — failed-step logs (when ‘magit-dash-gh-actions-include-failed-log’) index.json           — collection summary

** ~magit-dash-gh-pr-fetch~ [Command]

: (fn &optional PR-NUMBER)

Download comments and review threads for PR-NUMBER (or the current branch’s PR). When PR-NUMBER is nil, auto-detects the PR for the current branch.

Creates an artifact directory under plans/ containing: pr-info.json            — PR metadata and review decision pr-review-threads.json  — all review threads with resolved status pr-issue-comments.json  — top-level (non-review) comments index.json              — collection summary with per-thread creator/last-commentor

** ~magit-dash-gh-pr-dashboard-open~ [Command]

Open the pull request dashboard buffer.

** ~magit-dash-gh-prune-merged-branches~ [Command]

Open a menu to prune local branches whose PRs are merged or closed.

Per-repo cache (candidates + marked list) lives on the unified global cache keyed by repository toplevel. The menu loops until you select ‘exit menu’. The menu offers:

  - exit menu
  - refresh
  - prune all branches (no prompt)
  - prune all branches (with prompt)
  - mark branch for pruning
  - prune marked branches (when any are marked)
  - prune: BRANCH [marked]   (one entry per candidate)

** ~magit-dash-gh-prune-prefetch~

Seed the in-memory closed-PR cache from disk for the current repo. Makes no GitHub API calls; safe to call on status load. Skips silently when caching is disabled, not in a git repo, or the in-memory cache is already populated.

** ~magit-dash-gh-auth-switch~ [Command]

Switch the active ‘gh’ CLI account. When more than two accounts are configured, prompt to select which to switch to via ‘annotated-completing-read’. Otherwise switch directly to the other configured account.
